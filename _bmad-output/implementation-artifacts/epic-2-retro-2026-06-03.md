## ✅ 做得好的地方

### 1. 模型层先行带来高效复用

`ContentsModel` 和 `FavoritesModel` 在 Story 开始前就已经实现了完整 CRUD。每个 Story 只需在 controller 层拼接业务逻辑，没有重复造轮子。模型/数据库表/外键约束都提前就位，dev 阶段无需新建表或修改 schema。

### 2. Previous Story Intelligence 机制产生复利

每个 Story 的「Previous Story Intelligence」段落明确「原问题 → 本 Story 预防措施」映射：

- Story 2-1 review 发现的 `onMounted + watch + handleTabClick` 重复请求问题，从 2-2 起形成「统一 `loadData()` 入口」规约
- Story 2-4 引入 `isMounted + rawId` 守卫，在 2-5、2-6 被无缝复用
- Story 2-5 引入严格 ID 校验 `/^[1-9]\d*$/` + `Number.isSafeInteger`，2-6 复用扩展为 `parsePaginationParam`

### 3. 三层对抗式代码审查有效

`Blind Hunter / Edge Case Hunter / Acceptance Auditor` 三层 review 在 Story 2-5 一次性识别出 9 项 patch finding，包括 `parsePositiveContentId` 拒绝 `1e100` / `0x10` / `Infinity` / 前后空白这种边角输入——传统单层 review 抓不到。

### 4. 测试纪律良好

- 后端测试从 2-2 的 7 个增长到 2-6 的 36 个（4× 增长）
- 全部 mock 数据库，没有引入真实 DB 依赖
- 测试用例覆盖 401 / 400 / 404 / 500 / 默认值 / 边界值 / 异常输入

## ⚠️ 暴露的问题

### 1. Spec 偏离在多个 Story 中反复出现

- Story 2-1：前端 limit=50（spec 要求 20）
- Story 2-3：硬编码 page=1，spec 已指出分页尚未实现但留有 TODO
- Story 2-5：收藏状态查询被实现成串行（spec Dev Notes 明确要求并发 `Promise.allSettled`）
- Story 2-6：parsePositiveInteger 默认值兜底（spec 明确要求无效 → 400）

这些偏离都靠 code-review 阶段兜底——但 review 不应成为 spec 偏离的兜底网。

### 2. Dev Notes 中「已完整」声明不可信

Story 2-6 的 `FavoritesModel.findByUser` 标注「已完整，禁止重新实现」，但实施时发现 SQL 仅 `SELECT * FROM favorites`，没有 JOIN contents 表，返回字段根本无法渲染 ContentCard——AC #2 直接失败。dev-story 阶段浪费了时间在错误的「复用」上。

### 3. 测试基础设施不稳固

- `env.test.ts` 加载失败（envalid worker 异常）
- `content.controller.test.ts` 的 4 个 getNeighbors 用例长期失败（Story 2-4 之前就存在）

预存失败长期未修，新增测试跑不过时，开发者要花时间用 `git stash` 比对来证明「不是我的锅」，掩盖了真实回归风险。

### 4. 同类型 finding 反复出现

| 反复出现的问题 | 出现的 Story |
|----------------|--------------|
| JSON.parse 异常未处理 | 2-1, 2-4 |
| el-tag type 强转 any | 2-4 |
| examples/tags 类型 any | 2-1, 2-2 |
| AbortController 并发竞态 | 2-1, 2-2, 2-3 |
| 401/404 错误处理不精确 | 2-4, 2-5 |
| 路由切换守卫缺失 | 2-4 起形成模式 |

说明 review 修复是点状的，没有沉淀为规约或 linter 规则。

### 5. deferred-work.md 持续膨胀

Epic 2 累积了 18+ 项 deferred，其中 3 项与安全相关：

- CSRF 防护缺失（全站写接口依赖 cookie session）
- 写接口无速率限制（toggle / login / register）
- `FavoritesModel.toggle` 非事务 read-then-write 并发竞态（从 2-5 deferred 到 2-6，依然没解决）

### 6. Story 元数据缺失

多个 Story 的 `Agent Model Used` 字段未填（2-1/2-2/2.3/2.4），不利于追溯。
