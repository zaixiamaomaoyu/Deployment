# Story 2.3: 内容搜索功能

Status: done

## Story

As a 用户,
I want 搜索知识内容,
so that 我可以快速定位特定知识点。

## Acceptance Criteria

1. **Given** 内容列表已加载  
   **When** 在搜索框输入关键词  
   **Then** 实时显示匹配的内容

2. **Given** 搜索结果已展示  
   **When** 查看结果卡片  
   **Then** 高亮匹配的关键词

3. **Given** 搜索无匹配内容  
   **When** 页面展示结果  
   **Then** 显示友好提示（如「未找到相关内容，请尝试其他关键词」）

4. **Given** 用户同时使用了筛选和搜索  
   **When** 内容加载  
   **Then** 只显示同时满足筛选条件和搜索关键词的内容

5. **Given** 用户快速输入或切换条件  
   **When** 新请求发出  
   **Then** 自动取消之前的未完成请求（防止竞态覆盖）

## Dev Notes

### 关键复用点（禁止重复造轮子）

- **ContentsModel.findAll() 已支持 search 参数**：`backend/src/models/contents.model.ts` 的 `findAll(options)` 已经接受 `search?: string`，SQL WHERE 条件已自动拼接 `title LIKE ? OR description LIKE ? OR content LIKE ?`。开发者**直接复用**，禁止修改模型逻辑。

- **请求取消机制已就位**：`frontend/src/views/ContentsView.vue` 已使用 `AbortController` 实现请求取消。新增搜索逻辑时必须**保留并复用**现有 `abortController` 模式。

- **组合筛选模式已就位**：Story 2.2 已实现 `activeDomain` + `activeLevel` 组合筛选，通过统一 `loadData()` 入口读取当前值并请求。搜索应遵循同一模式：添加 `searchQuery` ref，变化时调用 `loadData()`，函数内部读取三个条件同时传递。

- **参数验证参考**：后端 `parseLevel` 已实现 null/空值/范围校验。`search` 参数校验参考此模式，增加长度限制即可：
  ```typescript
  function parseSearch(value: unknown): string | undefined {
    if (value == null || value === '') return undefined;
    const str = String(value).trim();
    if (str.length === 0) return undefined;
    if (str.length > 100) return str.slice(0, 100); // 或返回 400
    return str;
  }
  ```

- **前端 API 模式**：参考 `frontend/src/api/auth.ts`，使用统一 axios 实例。`getContents` 签名扩展示例：
  ```typescript
  export async function getContents(
    domain?: string,
    level?: number,
    search?: string,
    page = 1,
    limit = 20,
    signal?: AbortSignal
  ): Promise<ContentsResponse>
  ```

### 技术实现要点

**后端 search 参数处理：**
```typescript
const { domain, level, search, page = '1', limit = '20' } = req.query;
// ... domain / level 校验保持不变 ...

const parsedSearch = parseSearch(search);
// search 为可选参数，无需强制校验失败，空值直接忽略

const result = await ContentsModel.findAll({
  domain: domainStr,
  level: parsedLevel,
  search: parsedSearch,
  page: parsedPage,
  limit: parsedLimit,
});
```
- 注意：ContentsModel.findAll 中 `if (search)` 为 truthy 判断，空字符串已安全跳过。

**前端 debounce 实现：**
```typescript
import { ref, onMounted, onUnmounted } from 'vue'

const searchQuery = ref('')
let debounceTimer: ReturnType<typeof setTimeout> | null = null

function handleSearchInput() {
  if (debounceTimer) clearTimeout(debounceTimer)
  debounceTimer = setTimeout(() => {
    loadData()
  }, 300)
}

onUnmounted(() => {
  if (debounceTimer) clearTimeout(debounceTimer)
})
```
- 也可以考虑使用 `lodash-es/debounce` 如果项目已引入，但为减少依赖变动，推荐原生 setTimeout 方案。

**HighlightText 组件实现（安全无 v-html）：**
```vue
<script setup lang="ts">
import { computed } from 'vue'

const props = defineProps<{
  text: string
  keyword?: string
}>()

const segments = computed(() => {
  if (!props.keyword) return [{ text: props.text, match: false }]
  const escaped = props.keyword.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')
  const regex = new RegExp(`(${escaped})`, 'gi')
  const parts = props.text.split(regex)
  return parts.map(part => ({
    text: part,
    match: regex.test(part)
  }))
})
</script>

<template>
  <span>
    <mark
      v-for="(seg, i) in segments"
      :key="i"
      v-bind="seg.match ? { class: 'highlight-mark' } : {}"
    >{{ seg.text }}</mark>
  </span>
</template>

<style scoped>
.highlight-mark {
  background-color: #fef08a;
  color: #92400e;
  padding: 0 2px;
  border-radius: 2px;
}
</style>
```
- ⚠️ 避免使用 `v-for` + `v-bind` 对象在 `<mark>` 上的 hack，更清晰的做法是用 `span` + 条件 class：
  ```vue
  <template>
    <span>
      <template v-for="(seg, i) in segments" :key="i">
        <mark v-if="seg.match" class="highlight-mark">{{ seg.text }}</mark>
        <span v-else>{{ seg.text }}</span>
      </template>
    </span>
  </template>
  ```

**ContentsView 搜索逻辑：**
- `activeDomain`（string）+ `activeLevel`（number | undefined）+ `searchQuery`（string）共同决定请求参数
- `loadData()` 内部读取三个当前值，调用 `getContents(activeDomain, activeLevel, searchQuery.value, 1, 20, abortController.signal)`
- 注意：搜索时应重置 page 为 1（若后续支持分页）
- 空状态文案区分：
  - 无筛选有搜索且无结果 → 「未找到相关内容，请尝试其他关键词」
  - 有筛选无搜索且无结果 → 保持现有「该筛选条件下暂无内容，请尝试其他组合」
  - 混合条件无结果 → 「未找到匹配内容，请调整筛选条件或关键词」

## Previous Story Intelligence

### Story 2.1 学到的经验

- **ContentsModel 完整复用**：findAll / findByDomain / findByLevel / search 已就绪，不要创建新查询逻辑
- **参数验证必须严格**：page/limit 已做正整数校验，后续参数需同样严格
- **防止重复请求**：`onMounted` + `watch` + `handleTabClick` 组合导致重复 API 调用，修复方法是统一入口函数 `loadData()`
- **请求取消防止竞态**：快速切换标签时旧请求覆盖新结果，AbortController 必须保留
- **类型精确化**：`examples` / `tags` 使用 `unknown[]` / `string[]`
- **domain 白名单**：后端必须校验，防止无效参数导致全表扫描

### Story 2.2 学到的经验

- **统一 loadData() 入口**：所有筛选条件变化（domain/level/search）都应调用同一个 `loadData()`，内部读取当前 ref 值
- **parseLevel 边界处理**：`value == null || value === ''` 才返回 undefined，避免 `null` 误报 400
- **组合筛选顺序**：API 层同时传递 domain + level + search，由后端 ContentsModel 自动 AND 拼接
- **空状态文案细化**：不同条件组合可展示不同提示语
- **AbortController 并发竞态**：`finally` 中 `abortController = null` 在快速连续触发时可能覆盖新实例，当前代码已存在此问题，本 Story 保留原有行为不引入新修复
