# Story 3.2: 决策树数据设计

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 平台开发者,
I want 设计完整的决策树问题、答题路径与推荐方案数据,
so that `DecisionTree` 组件（Story 3-1 已交付）能直接消费这份数据，根据用户回答推荐合适的部署方案，并由 Story 3-3 结果页与 Story 3-4 步骤指南页进一步展示推荐理由与详细步骤。

## Acceptance Criteria

> 本 Story **仅交付静态数据与类型扩展 + 数据校验**，不涉及结果页 UI（属 Story 3-3）、不涉及步骤指南内容（属 Story 3-4）、不涉及后端 API。决策树数据为前端硬编码的静态资源，**不来自后端**。

1. **Given** Story 3-1 已定义 `DecisionTreeResult = { planId, planName }`
   **When** 本 Story 扩展类型以承载「推荐理由」等附加信息
   **Then** 在 `frontend/src/types/decision-tree.ts` 上**向后兼容**地新增**可选**字段（不破坏 3-1 现有测试 fixture）：
   - `reason?: string[]` — 推荐理由（1-3 条简短描述，用于结果页渲染）
   - `category?: 'static' | 'spa' | 'ssr' | 'fullstack' | 'container'` — 方案大类
   - `difficulty?: 'beginner' | 'intermediate' | 'advanced'` — 推荐目标用户水平
   **And** 不修改任何已有字段，不改变 `DecisionTreeOption`/`DecisionTreeNode`/`DecisionTreeData` 形状
   **And** Story 3-1 已有的 `useDecisionTree.spec.ts` / `DecisionTree.spec.ts` 全量通过（无回归）

2. **Given** 需要一份独立的「部署方案」详情注册表，供 Story 3-3/3-4 消费
   **When** 在 `frontend/src/types/deployment-plan.ts` 定义 `DeploymentPlan` 接口
   **Then** 至少包含：
   - `planId: string` — 唯一标识（与决策树叶子 `result.planId` 对齐）
   - `planName: string` — 方案名（与 `result.planName` 一致）
   - `category: 'static' | 'spa' | 'ssr' | 'fullstack' | 'container'`
   - `difficulty: 'beginner' | 'intermediate' | 'advanced'`
   - `priceRange: 'free' | 'low' | 'medium' | 'high'` — 价格区间
   - `summary: string` — 一句话介绍（≤ 60 字符）
   - `reason: string[]` — 推荐理由（1-3 条）
   - `pros: string[]` — 优点（≥ 2 条）
   - `cons: string[]` — 缺点 / 限制（≥ 1 条）
   - `suitableFor: string[]` — 适合人群（≥ 1 条）
   - `externalUrl?: string` — 官方链接（可选）

3. **Given** 决策树需要覆盖常见前端部署场景
   **When** 在 `frontend/src/data/decision-tree-data.ts` 导出 `decisionTreeData: DecisionTreeData`
   **Then** 问题**至少涵盖**以下维度（PRD/epics.md/Story 3.2 AC）：
   - 项目类型（静态站点 / SPA / SSR / 全栈 / 容器化）
   - 预算（免费 / 低成本 / 可付费）
   - 技术水平（新手 / 熟悉 Linux / 熟悉容器）
   - 数据持久化需求（无 / 需要）
   **And** 树的深度 ≥ 3 层、≤ 6 层（避免过浅无差别、过深疲劳）
   **And** 节点总数 ≥ 6、≤ 20（含问题节点与叶子节点）
   **And** 每个非叶子节点 options 数量 ∈ [2, 5]
   **And** 每个叶子节点的 `result.planId` 必须能在 `deploymentPlans` 中找到对应条目

4. **Given** Story 3-1 的 composable `progress` 估算逻辑会沿 `nextId` 走到叶子
   **When** 设计决策树数据
   **Then** 数据中**不存在环**（A.nextId → B、B.nextId → A）
   **And** 每条路径都能在 ≤ 6 步内到达叶子
   **And** 从根节点出发，所有可达叶子深度差异 ≤ 3（避免进度条前后大幅跳动）

5. **Given** 决策树叶子映射到部署方案
   **When** 在 `frontend/src/data/deployment-plans.ts` 导出 `deploymentPlans: Record<string, DeploymentPlan>`
   **Then** 注册表至少包含 **10 个**独立 `planId`，覆盖以下场景（不限于）：
   - 至少 3 个免费静态托管（如 GitHub Pages、Vercel 静态、Cloudflare Pages、Netlify 免费版）
   - 至少 1 个 Serverless/Functions 方案
   - 至少 2 个全栈 PaaS（如 Railway、Render）
   - 至少 2 个 VPS 自建方案（如 宝塔面板、Docker Compose）
   - 至少 1 个容器化专用方案
   **And** 每个 `planId` 在 `decisionTreeData` 中**至少被一个叶子引用**（无孤立 plan）
   **And** `planId` 全部为小写 kebab-case（如 `vercel-static`、`vps-docker`）

6. **Given** 数据是前端硬编码的静态资源
   **When** 在前端代码中消费
   **Then** 通过命名导出访问：
   - `import { decisionTreeData } from '@/data/decision-tree-data'`
   - `import { deploymentPlans } from '@/data/deployment-plans'`
   **And** **不**创建 Pinia store（数据静态、无需响应式）
   **And** **不**新建 API 端点（决策树数据不来自后端）

7. **Given** 数据存在人为出错的可能（漏字段、错引用、出现环）
   **When** 运行数据校验测试 `frontend/src/data/__tests__/decision-tree-data.spec.ts`
   **Then** 测试用例覆盖：
   - 根节点存在且 options 非空
   - 所有 `nextId` 指向已定义节点，或为 `null`（叶子）
   - 所有叶子都有 `result`，且 `result.planId` 在 `deploymentPlans` 中存在
   - 树中无环（DFS 检测）
   - 树的深度 ≥ 3、≤ 6
   - 每个非叶子节点 options 数量 ∈ [2, 5]
   - 每个节点 `id` 唯一
   **And** 测试**不**依赖任何 DOM / Vue 组件，纯数据断言

8. **Given** `deploymentPlans` 注册表需要完整性校验
   **When** 运行 `frontend/src/data/__tests__/deployment-plans.spec.ts`
   **Then** 测试用例覆盖：
   - 每个 plan 的 `planId` / `planName` / `category` / `difficulty` / `priceRange` / `summary` / `reason` / `pros` / `cons` / `suitableFor` 全部非空
   - `summary` 长度 ≤ 60 字符
   - `reason.length` ∈ [1, 3]
   - `pros.length` ≥ 2
   - `cons.length` ≥ 1
   - `suitableFor.length` ≥ 1
   - `externalUrl`（若存在）以 `https://` 开头
   - 每个 plan 的 `category` 在枚举集合内
   - 每个 plan 的 `difficulty` 在枚举集合内
   - 每个 plan 的 `priceRange` 在枚举集合内

10. **Given** 开发者可能在 IDE 中查看数据
    **When** 编辑 `decision-tree-data.ts` 或 `deployment-plans.ts`
    **Then** 类型严格（无 `any`）、字段对齐 `DecisionTreeResult` / `DeploymentPlan`
    **And** 关键决策（如「为何 GitHub Pages 不放在免费首选位」）以**简短中文注释**解释（≤ 1 行/节点，仅对非显而易见的决策）
    **And** 文件顶部有 1 个文件级注释块说明数据来源与维护规则

### 关键复用点（禁止重复造轮子）

- **不要新建 Pinia store**：决策树数据为静态资源，直接 `import`，**禁止**创建 `useDecisionTreeDataStore`。Pinia 仅用于需要跨组件响应式的状态（如 `useUserStore`）。
- **不要修改 Story 3-1 的 composable / 组件 / 既有测试**：仅扩展类型（向后兼容），不修改既有逻辑。如发现 3-1 缺陷，记录到本 Story 的 Completion Notes 但**不在本 Story 修复**（避免范围蔓延）。
- **类型扩展模式**：参考 Story 3-1 在 `frontend/src/types/decision-tree.ts` 的接口定义风格，新增字段一律 **可选（`?:`）**，保证 3-1 fixture（`result: { planId: 'vps', planName: 'VPS 自建' }`）继续合法。
- **不要新增依赖**：技术栈已包含 `vue@3.4` + `vitest@2.1`，禁止引入 `zod` / `joi` / `class-validator` 等运行时校验库。所有校验在测试用例中用纯 TypeScript 实现。
- **数据导出方式**：参考 `frontend/src/api/contents.ts` 的命名导出风格（`export const xxx = ...`），不使用默认导出（与 `project-context.md#导入/导出模式` 一致）。
- **文件命名**：参考 `project-context.md#文件命名约定`，数据文件用 camelCase（`decision-tree-data.ts`、`deployment-plans.ts`），类型文件用 camelCase（`deployment-plan.ts`）。
- **测试组织**：参考 `frontend/src/composables/__tests__/useDecisionTree.spec.ts`，测试文件就近放置在 `__tests__/` 子目录。
- **中文文案**：所有面向用户的字段（`planName`、`summary`、`reason`、`pros`、`cons`、`suitableFor`）使用简体中文，与 `CLAUDE.md#必须全程使用简体中文` 一致。
- **`planId` 命名**：全部小写 kebab-case，参考现有项目 slug 命名（如 `vercel-static`、`vps-docker`、`github-pages`）。

```typescript
    const root = decisionTreeData.nodes[decisionTreeData.rootId]
    expect(root).toBeDefined()
    expect(root.options.length).toBeGreaterThanOrEqual(2)
  })

  it('所有 nextId 指向已定义节点或为 null', () => {
    for (const node of Object.values(decisionTreeData.nodes)) {
      for (const opt of node.options) {
        if (opt.nextId !== null) {
          expect(decisionTreeData.nodes[opt.nextId]).toBeDefined()
        }
      }
    }
  })

  it('叶子节点的 result.planId 全部在 deploymentPlans 中存在', () => {
    for (const node of Object.values(decisionTreeData.nodes)) {
      for (const opt of node.options) {
        if (opt.nextId === null) {
          expect(opt.result).toBeDefined()
          expect(deploymentPlans[opt.result!.planId]).toBeDefined()
        }
      }
    }
  })

  it('树中无环', () => {
    const visited = new Set<string>()
    const dfs = (id: string, path: string[]) => {
      if (path.includes(id)) {
        throw new Error(`检测到环：${[...path, id].join(' → ')}`)
      }
      if (visited.has(id)) return // 已遍历过该子树
      visited.add(id)
      const node = decisionTreeData.nodes[id]
      if (!node) return
      for (const opt of node.options) {
        if (opt.nextId !== null) dfs(opt.nextId, [...path, id])
      }
    }
    dfs(decisionTreeData.rootId, [])
  })

  it('树的深度 ∈ [3, 6]', () => {
    const depthOf = (id: string, visited = new Set<string>()): number => {
      if (visited.has(id)) return 0
      visited.add(id)
      const node = decisionTreeData.nodes[id]
      if (!node || node.options.length === 0) return 0
      const childDepths = node.options
        .filter((o) => o.nextId !== null)
        .map((o) => depthOf(o.nextId!, new Set(visited)))
      return childDepths.length === 0 ? 1 : 1 + Math.max(...childDepths)
    }
    const depth = depthOf(decisionTreeData.rootId)
    expect(depth).toBeGreaterThanOrEqual(3)
    expect(depth).toBeLessThanOrEqual(6)
  })

  it('每个非叶子节点 options 数量 ∈ [2, 5]', () => {
    for (const node of Object.values(decisionTreeData.nodes)) {
      if (node.options.some((o) => o.nextId !== null)) {
        expect(node.options.length).toBeGreaterThanOrEqual(2)
        expect(node.options.length).toBeLessThanOrEqual(5)
      }
    }
  })

  it('节点 id 全局唯一', () => {
    const ids = Object.keys(decisionTreeData.nodes)
    expect(new Set(ids).size).toBe(ids.length)
  })
})
```

**集成测试骨架（`useDecisionTree.integration.spec.ts`）：**
```typescript
import { describe, it, expect } from 'vitest'
import { useDecisionTree } from '@/composables/useDecisionTree'
import { decisionTreeData } from '@/data/decision-tree-data'
import { deploymentPlans } from '@/data/deployment-plans'

describe('useDecisionTree × decisionTreeData 集成', () => {
  // DFS 走通每一条根→叶子路径
  function walkAllPaths(
    state: ReturnType<typeof useDecisionTree>,
    onLeaf: (planId: string, depth: number) => void,
  ) {
    const node = state.currentNode.value
    if (!node) return
    for (const opt of node.options) {
      const outcome = state.selectOption(opt)
      if (outcome?.type === 'complete') {
        onLeaf(outcome.payload.result.planId, outcome.payload.answers.length)
        state.goBack()
      } else if (outcome?.type === 'advance') {
        walkAllPaths(state, onLeaf)
        state.goBack()
      }
    }
  }

  it('所有叶子路径返回的 planId 都在 deploymentPlans 中存在', () => {
    const state = useDecisionTree(decisionTreeData)
    const leaves: string[] = []
    walkAllPaths(state, (planId) => leaves.push(planId))
    expect(leaves.length).toBeGreaterThanOrEqual(8) // ≥ 8 条路径
    for (const planId of leaves) {
      expect(deploymentPlans[planId]).toBeDefined()
    }
  })
})
```

### 关键设计决策

1. **数据静态而非 API**：决策树内容是产品设计的一部分，变更频率低，前端硬编码更利于 Review 与版本控制；后端 API 仅用于真正动态的数据（用户、内容、反馈）。
2. **类型向后兼容扩展**：Story 3-1 已有的 fixture 不能因本 Story 失败，所有新增字段一律 `?:` 可选。
3. **plan 注册表与树分离**：决策树定义「分支逻辑」，plans 注册表定义「方案详情」。Story 3-3 结果页通过 `planId` 桥接两者，职责清晰。
4. **数据校验放在测试中，而非运行时**：避免引入 `zod` 等运行时校验库；CI 中跑测试即可发现数据错误，运行时无性能损耗。
5. **`reason` 既在 `DecisionTreeResult` 又在 `DeploymentPlan` 中**：树叶子上的 `reason` 用于结果页头部简短展示（1-2 条），plans 中的 `reason` 是完整版本（1-3 条）。两者**可以**重复，但 plans 中的应更详细。如果开发者认为冗余，可在 result 中只保留 `planId/planName`，由 plans 查询 reason —— 推荐此方案以避免数据漂移。
   - **推荐做法**：`DecisionTreeResult.reason` 留空（不填），结果页直接从 `deploymentPlans[planId].reason` 读取。本 Story 在 `DecisionTreeResult` 上保留可选 `reason` 字段仅为未来扩展（如 A/B 测试不同推荐文案）。
6. **测试通过 DFS 自动遍历**：避免每条路径手写测试用例，DFS 走通所有路径，新增节点自动覆盖。
7. **不集成到页面**：本 Story 仅交付数据，不修改任何 `views/` 或 `router/`。集成由 Story 3-3 负责（结果页消费数据）。

### 性能考虑

- 决策树数据 < 20 节点、plans 注册表 < 20 条，整体 < 5KB（gzip 后 < 2KB），直接 `import` 无需懒加载。
- 数据为纯对象，无响应式开销（不包 `reactive` / `ref`）。
- 测试 DFS 时间复杂度 O(N + E)，对 20 节点规模瞬时完成。

### 安全考虑

- 数据为静态硬编码，**不**渲染用户输入，无 XSS 风险。
- `externalUrl` 必须以 `https://` 开头（测试断言），避免 mixed content。
- 不涉及任何用户敏感信息（无 openid、session、token）。
- 文案中**禁止**包含外部链接、推广代码、affiliate ID。
