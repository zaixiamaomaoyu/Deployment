# Story 3.3: 决策结果展示页

Status: ready-for-dev

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 用户,
I want 查看决策树的推荐结果,
So that 我知道应该选择哪种部署方案。

## Acceptance Criteria

> 本 Story **交付结果页视图组件 + 路由集成**，不涉及步骤指南内容（属 Story 3-4）、不涉及后端 API。

1. **Given** 用户完成决策树问答（通过 DecisionTree 组件的 `complete` emit）
   **When** 结果页组件接收 `DecisionTreeCompletePayload`
   **Then** 显示推荐方案的名称（`result.planName`）
   **And** 从 `deploymentPlans[planId]` 读取并展示 `reason`（推荐理由）
   **And** 推荐理由使用 `<el-tag>` 或 `<el-alert>` 样式展示（每条理由一行）

2. **Given** 结果页显示推荐方案
   **When** 用户点击「查看步骤指南」按钮
   **Then** 路由跳转到步骤指南页（如 `/deployment/result/:planId` 或 `/deployment/steps` 并携带 planId）
   **And** 或路由跳转到步骤指南页并自动选择对应方案（由路由参数控制）

3. **Given** 结果页显示推荐方案
   **When** 用户点击「重新选择」按钮
   **Then** 路由跳转回决策树页（如 `/deployment/decision-tree` 或返回上一页）
   **And** DecisionTree 组件保持当前状态（可选：重置为根节点）

4. **Given** 结果页加载
   **When** `planId` 在 `deploymentPlans` 中不存在
   **Then** 显示友好错误：「未找到推荐的部署方案，请重新选择」
   **And** 提供「重新选择」按钮

5. **Given** 用户已完成决策树
   **When** 查看结果页
   **And** 渲染方案详情卡片
   **Then** 方案卡片显示：
   - 方案名称（`planName`）
   - 推荐理由（`reason` 数组，1-3 条）
   - 方案标签（category + difficulty）
   - 方案价格区间（`priceRange`，用 `<el-tag>` 或 `<el-rate>`）
   - 适合人群（`suitableFor`，用 `<el-tag>` 或列表形式）

6. **Given** 用户在移动端（宽度 < 768px）
   **When** 渲染结果页
   **Then** 方案卡片垂直堆叠
   **And** 按钮区域固定在底部或占满宽度
   **And** 文字大小自适应

7. **Given** 结果页展示方案详情
   **When** 用户访问结果页时未提供 `planId` 参数
   **Then** 自动跳转回决策树页或显示「未选择方案」提示
   **And** 不抛出 JS 运行时错误

## Dev Notes

### 关键复用点（禁止重复造轮子）

- **不要新建 store**：本组件为纯展示组件，数据来自父组件（或路由参数），**禁止**创建 Pinia store。
- **不要新增依赖**：技术栈已包含 `vue@3.4` + `element-plus@2.13` + `@vue/test-utils@2.4` + `vitest@2.1`，禁止引入额外工具库。
- **数据来源**：方案详情从 `deploymentPlans[planId]` 读取（Story 3-2 交付的静态数据），不是 API。
- **类型导出位置**：类型在 `frontend/src/types/` 目录，与 `architecture.md` 第 353-405 行约定一致。
- **CSS 变量复用**：使用 `architecture.md` 中定义的全局变量（`--primary-color`、`--spacing-md` 等），禁止新建主题变量。
- **测试组织**：参考 `frontend/src/views/__tests__/FavoritesView.spec.ts` 测试组织模式。
- **Element Plus 组件**：方案卡片使用 `<el-card>`，标签使用 `<el-tag>`，按钮使用 `<el-button>`。
- **中文文案**：所有面向用户的字段（`planName`、`reason`、`category`、`difficulty`、`priceRange`、`suitableFor`）使用简体中文。
- **错误处理**：`planId` 不存在时显示友好错误，提供「重新选择」按钮，不抛出 JS 错误。

### 技术实现要点

**组件骨架（`src/views/DecisionResultView.vue`）：**
```vue
<script setup lang="ts">
import { computed } from 'vue'
import { useRouter } from 'vue-router'
import type { DecisionTreeCompletePayload } from '@/types/decision-tree'
import { deploymentPlans } from '@/data/deployment-plans'

interface Props {
  result: DecisionTreeCompletePayload
}

const props = defineProps<Props>()
const emit = defineEmits<{
  (e: 'go-back'): void
  (e: 'view-steps'): void
}>()

const router = useRouter()

// 从 deploymentPlans 读取方案详情，不存在时显示空状态
const plan = computed(() => deploymentPlans[props.result.planId])

function handleGoBack() {
  emit('go-back')
  // 或 router.back()
}

function handleViewSteps() {
  emit('view-steps')
  // 或 router.push(`/deployment/steps?planId=${props.result.planId}`)
}
</script>

<template>
  <div v-if="plan" class="decision-result">
    <!-- 方案名称 -->
    <h1 data-testid="dr-result-name" class="dr-title">
      {{ plan.planName }}
    </h1>

    <!-- 方案详情卡片 -->
    <el-card data-testid="dr-card" class="dr-card">
      <!-- 推荐理由 -->
      <div data-testid="dr-reasons" class="dr-reasons">
        <el-alert
          v-for="(reason, idx) in plan.reason"
          :key="idx"
          :type="idx === 0 ? 'success' : 'info'"
          :closable="false"
        >
          {{ reason }}
        </el-alert>
      </div>

      <!-- 标签 -->
      <div data-testid="dr-tags" class="dr-tags">
        <el-tag>{{ plan.category }}</el-tag>
        <el-tag type="info">{{ plan.difficulty }}</el-tag>
        <el-tag :type="priceRangeType(plan.priceRange)">
          {{ priceRangeLabel(plan.priceRange) }}
        </el-tag>
      </div>

      <!-- 适合人群 -->
      <div data-testid="dr-suitable-for" class="dr-suitable-for">
        <span class="dr-suitable-for-label">适合人群：</span>
        <el-tag
          v-for="(user, idx) in plan.suitableFor"
          :key="idx"
          style="margin-right: 8px"
        >
          {{ user }}
        </el-tag>
      </div>
    </el-card>

    <!-- 按钮区域 -->
    <div data-testid="dr-actions" class="dr-actions">
      <el-button data-testid="dr-view-steps" @click="handleViewSteps">
        查看步骤指南
      </el-button>
      <el-button data-testid="dr-go-back" @click="handleGoBack">
        重新选择
      </el-button>
    </div>
  </div>

  <!-- 错误状态：planId 不存在 -->
  <div v-else data-testid="dr-error" class="dr-error">
    <p>未找到推荐的部署方案，请重新选择</p>
    <el-button @click="handleGoBack">重新选择</el-button>
  </div>
</template>
```

**辅助函数：**
```typescript
function priceRangeType(range: 'free' | 'low' | 'medium' | 'high'): 'success' | 'warning' | 'danger' | 'info' {
  const map: Record<string, typeof range> = {
    free: 'free',
    low: 'warning',
    medium: 'danger',
    high: 'info',
  }
  return map[range] || 'info'
}

function priceRangeLabel(range: 'free' | 'low' | 'medium' | 'high'): string {
  const map: Record<string, string> = {
    free: '免费',
    low: '低成本',
    medium: '中等成本',
    high: '高成本',
  }
  return map[range] || range
}
```

**路由配置（`src/router/index.ts`）：**
```typescript
{
  path: '/deployment/decision-tree/result',
  name: 'decision-result',
  component: () => import('@/views/DecisionResultView.vue'),
  props: (route) => ({
    // 可选：传递 planId 用于错误恢复
    planId: route.query.planId as string | undefined
  }),
}
```

**关键设计决策：**

1. **数据源选择**：从 `deploymentPlans[planId]` 读取方案详情，而非从 `result.reason` 读取。理由：
   - `result.reason` 在 Story 3-2 中已被注释为「数据中默认不填充」
   - plans 中的 reason 更详细（1-3 条），tree 中的 reason 留空
   - 避免数据漂移（tree 与 plans reason 不一致）
   - 未来可扩展 A/B 测试不同推荐文案

2. **错误处理**：`planId` 不存在时显示友好错误而非崩溃。用户可能：
   - 直接访问结果页 URL（带无效 planId）
   - 数据文件被误改/删除
   - 显示错误并提供「重新选择」按钮，引导用户回到决策树

3. **路由跳转策略**：
   - 「重新选择」跳转回决策树页（或浏览器 back），由父组件（路由）决定是否重置 DecisionTree 状态
   - 「查看步骤指南」跳转到步骤指南页（由 Story 3-4 负责路由和页面），当前 Story 仅触发跳转

4. **样式复用**：使用 Element Plus 组件（`el-card` / `el-tag` / `el-alert` / `el-button`），CSS 变量控制颜色和间距，保持与项目一致。

### 接口契约（组件 props/emits）

| 接口 | 类型 | 说明 |
|------|------|------|
| Prop `result` | `DecisionTreeCompletePayload` | 决策树完成时的 payload（含 planId、answers） |
| Emit `go-back` | `() => void` | 用户点击「重新选择」时触发 |
| Emit `view-steps` | `() => void` | 用户点击「查看步骤指南」时触发 |

### 性能考虑

- `deploymentPlans` 是纯对象，无响应式开销，直接 `import` 即可。
- 方案详情在页面初始化时计算一次（`computed`），缓存复用。
- 文件大小 < 5KB（gzip 后 < 2KB），无需懒加载。

### 安全考虑

- 所有文案来自前端硬编码数据（Story 3-2 设计），无用户输入渲染，无 XSS 风险。
- `externalUrl` 使用官方链接，禁止 affiliate 链接。

### 测试要求

- **组件测试**：使用 `@vue/test-utils` 的 `mount`，Mock `deploymentPlans` 导入。
- **覆盖率目标**：组件渲染分支 ≥ 80%。
- **手动测试场景**：
  1. 桌面浏览器显示方案详情，按钮可点击
  2. 移动端（375x667）布局正常，按钮区域可点击
  3. 无效 `planId` 显示错误提示
  4. 键盘 Tab / Enter 全流程操作
  5. 与 DecisionTree 组件集成测试（complete emit → 结果页 props）

## Previous Story Intelligence

### Story 3-2 学到的经验

- **类型严格化**：`DeploymentPlan` 接口所有字段类型枚举化（`category` / `difficulty` / `priceRange`），避免字符串字面量误用。
- **数据静态而非 API**：决策树数据前端硬编码，本 Story 仅消费，无需新增 API。
- **数据完整性校验**：`deploymentPlans` 注册表测试覆盖字段非空、枚举校验、长度限制。
- **不修改预存代码**：3-2 未修改 3-1 的任何文件，仅扩展类型且所有新增字段为可选。
- **中文文案**：所有面向用户的字段使用简体中文，与 `CLAUDE.md` 一致。
- **testid 命名**：stable testid 是 UI 集成测试与 E2E 的基础。

### Story 3-1 学到的经验

- **composable 与组件分离**：业务逻辑在 composable，组件纯展示，便于测试。
- **props/emits 契约明确**：组件接口在 Dev Notes 中显式定义，便于后续 Story 消费。
- **ARIA 可访问性**：选项使用 `role="button" + aria-pressed`，符合 WCAG 2.1 AA。
- **组件测试组织**：单元测试（composable）+ 组件测试分离，避免一个文件膨胀。
