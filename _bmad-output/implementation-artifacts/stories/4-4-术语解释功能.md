# Story 4.4: 术语解释功能

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

作为用户,
我希望 AI 解释部署相关术语,
以便我可以理解专业名词。

## Acceptance Criteria

1. **Given** 用户询问术语（如「什么是 Nginx」）
   **When** AI 回复
   **Then** 返回通俗易懂的解释
   **And** 包含示例或类比
   **And** 提供相关学习链接

2. **Given** 用户打开 AI 助手面板且对话为空
   **When** 显示空状态
   **Then** 展示常见术语快捷标签（如 Nginx、Docker、SSH、CI/CD）
   **And** 点击标签自动发送对应的术语询问

3. **Given** AI 正在解释术语
   **When** 回复内容包含 Markdown 格式
   **Then** 前端正确渲染定义、示例、相关链接等结构
   **And** 链接可点击跳转至知识内容详情页

4. **Given** 用户发送的术语问题语义模糊
   **When** AI 无法确定具体术语
   **Then** AI 友好地请求澄清
   **And** 给出可能相关的术语猜测

**Markdown 链接安全处理：**

```typescript
function renderMarkdown(content: string): string {
  const rawHtml = marked.parse(content, { async: false }) as string
  // DOMPurify 先清理
  const cleanHtml = DOMPurify.sanitize(rawHtml)
  // 为外部链接添加 target="_blank"，站内链接保留默认行为用于路由拦截
  return cleanHtml.replace(
    /<a\s+href="([^"]+)"/g,
    (match, url: string) => {
      if (url.startsWith('http://') || url.startsWith('https://')) {
        return `<a href="${url}" target="_blank" rel="noopener noreferrer"`
      }
      return match
    }
  )
}
```

> 注意：站内链接（如 `/content/123`）点击后默认会触发整页刷新。如需使用 Vue Router 无刷新跳转，可在组件挂载后通过事件委托为 `.ac-message__content a[href^="/content/"]` 添加点击拦截。此为可选增强，非本 Story AC 强制要求。

### 关键设计决策

1. **不新增独立 API 端点**：通过优化 system prompt 即可让现有 `POST /api/ai/chat` 具备术语解释能力，避免接口冗余
2. **快捷标签只在前端实现**：不增加后端术语库，降低 story 复杂度；后续 Epic 5（速查手册）可扩展为结构化术语数据
3. **AI 生成的相关链接为文本链接**：因 contents 表数据已存在，AI 可基于知识生成指向 `/content/:id` 的链接。链接是否有效取决于 AI 幻觉控制，MVP 阶段可接受
4. **保持 `streamChat` 和 `useAIChat` 接口不变**：前端架构稳定，修改只限于 UI 层

### 接口契约

| 接口/组件 | 变更 | 说明 |
|----------|------|------|
| `POST /api/ai/chat` | 无签名变更 | system prompt 增强，返回内容格式改变 |
| `streamChat()` | 无变更 | `frontend/src/api/ai.ts` 不需要修改 |
| `useAIChat.sendMessage()` | 无变更 | 快捷标签直接调用现有方法 |
| `AIChat.vue` | 新增 `quickTerms`、`handleQuickTerm` | UI 层增强 |
| `renderMarkdown()` | 增强链接处理 | 外部链接新开标签，站内链接保留 |

### 性能考虑

- 快捷标签为静态数组，无额外 API 请求
- Markdown 链接替换使用正则单次扫描，不影响长文本渲染性能
- 不改变 SSE 数据流格式，流式输出性能与 Story 4-3 一致

### 安全考虑

- 继续使用 `DOMPurify.sanitize` 过滤 AI 生成的 HTML，防止 XSS
- 外部链接强制 `target="_blank"` + `rel="noopener noreferrer"`，防止标签页钓鱼
- 不修改后端输入校验逻辑，消息长度限制 2000 字符仍然生效
