## Story

As a 平台开发者,
I want 开发可复用的 `DecisionTree` 问答式决策树组件,
so that 后续的部署方案引导页（Story 3-3）可以直接注入决策数据并渲染问答流程，让用户一步步选出适合自己的部署方案。

## Acceptance Criteria

> 本 Story 仅交付**纯前端展示组件**，不涉及决策数据设计（属 Story 3-2）、不涉及结果页/步骤指南（属 Story 3-3）、不涉及后端 API。

1. **Given** 父组件传入合法的决策树数据（含根节点 `id`、`question`、`options`）
   **When** 渲染 `DecisionTree` 组件
   **Then** 显示当前节点的问题文本
   **And** 显示该节点所有选项作为可点击卡片按钮
   **And** 选项按钮文案与 `option.label` 一致

2. **Given** 当前节点有 N 个选项
   **When** 渲染选项列表
   **Then** 选项按钮以纵向或网格排列（≥2 个时纵向，移动端单列）
   **And** 每个按钮具备清晰的 hover / focus / active 视觉状态
   **And** 每个按钮可键盘聚焦（Tab 顺序自然）

3. **Given** 用户点击某选项 `option`
   **When** 该选项的 `nextId` 存在（即非叶子节点）
   **Then** 组件前进到 `nextId` 指向的节点
   **And** 显示新节点的问题与选项
   **And** 切换有过渡动画（≤300ms，遵循 `prefers-reduced-motion`）

4. **Given** 用户点击某选项 `option`
   **When** 该选项的 `nextId` 为 `null`（叶子节点）且 `option.result` 存在
   **Then** 组件 **不**渲染下一题
   **And** 通过 `emit('complete', { answers, result })` 把累计答题路径和推荐结果抛给父组件
   **And** 在组件内部展示「推荐方案：xxx」的简短确认态（含「重新选择」按钮）

5. **Given** 用户已经回答了至少 1 题
   **When** 查看组件底部
   **Then** 显示进度指示器：`当前题号 / 总题号` 与圆点条（如 `●●○○○`）
   **And** 总题号按当前已走路径深度估算（沿当前节点继续走到任意叶子的最大步数 + 当前已答题数），允许保守取整
   **And** 第 1 题时进度为 1/N，最后一题前进到叶子后进度为 N/N

6. **Given** 用户已回答 ≥1 题
   **When** 点击「上一题」按钮
   **Then** 回退到前一题，恢复前题原选项的未选中状态
   **And** 答题历史栈中弹出当前题
   **And** 进度指示器同步回退
   **And** 第 1 题时「上一题」按钮置灰禁用

7. **Given** 用户已到达叶子节点（推荐结果态）
   **When** 点击「重新选择」按钮
   **Then** 重置答题历史栈与当前节点为根节点
   **And** 进度指示器回到第 1 题
   **And** 不触发 `emit('complete')`（由父组件决定是否处理）

8. **Given** 父组件传入空数据或非法数据（如根节点 `options` 为空数组）
   **When** 组件挂载
   **Then** 显示空状态：「决策树数据为空」
   **And** 不抛出 JS 运行时错误
   **And** 通过 `console.warn` 提示开发者

9. **Given** 用户使用键盘操作
   **When** Tab 进入选项区，使用 `↑/↓` 或 `←/→` 切换焦点，按 `Enter/Space` 选中
   **Then** 选项可访问，符合 WCAG 2.1 AA
   **And** 选项按钮具备 `role="radio"`、`aria-checked`、`aria-label`（参考 ux-design-specification.md#关键实现）
   **And** 焦点可见（visible focus ring）

10. **Given** 屏幕宽度 < 768px（移动端）
    **When** 渲染组件
    **Then** 组件撑满可用宽度（max-width: 100%）
    **And** 选项按钮单列纵向排列
    **And** 文案字号自适应（最小 14px）

11. **Given** 组件以 `data-testid` 命名根元素、问题、选项、进度、上一题/重新选择按钮
    **When** 测试用例或 E2E 选择元素
    **Then** 以下 testid 稳定可用：
    - `decision-tree`（根）
    - `dt-question`（问题文本）
    - `dt-option-${optionId}`（选项按钮）
    - `dt-progress`（进度文字）
    - `dt-progress-dots`（圆点条）
    - `dt-back`（上一题）
    - `dt-restart`（重新选择）
    - `dt-result`（推荐结果文案）

**composable 签名（`src/composables/useDecisionTree.ts`）：**
```typescript
import { ref, computed } from 'vue'
import type {
  DecisionTreeData,
  DecisionTreeNode,
  DecisionTreeOption,
  DecisionTreeAnswer,
  DecisionTreeCompletePayload,
} from '@/types/decision-tree'

export type SelectOutcome =
  | { type: 'advance'; nextNode: DecisionTreeNode }
  | { type: 'complete'; payload: DecisionTreeCompletePayload }

export function useDecisionTree(data: DecisionTreeData) {
  const currentNodeId = ref(data.rootId)
  const answers = ref<DecisionTreeAnswer[]>([])

  const currentNode = computed<DecisionTreeNode | null>(() =>
    data.nodes[currentNodeId.value] ?? null,
  )

  const isRoot = computed(() => currentNodeId.value === data.rootId)
  const canGoBack = computed(() => answers.value.length > 0)
  const empty = computed(() => !currentNode.value || currentNode.value.options.length === 0)

  function estimateMaxDepth(nodeId: string, visited = new Set<string>()): number {
    if (visited.has(nodeId)) return 0 // 环检测
    visited.add(nodeId)
    const node = data.nodes[nodeId]
    if (!node || node.options.length === 0) return 0
    const childDepths = node.options
      .filter((o) => o.nextId !== null)
      .map((o) => 1 + estimateMaxDepth(o.nextId as string, new Set(visited)))
    return childDepths.length === 0 ? 1 : Math.max(...childDepths)
  }

  const progress = computed(() => {
    const answered = answers.value.length + 1 // 当前题也算 1
    const total = answered - 1 + estimateMaxDepth(currentNodeId.value)
    return { current: answered, total: Math.max(total, answered) }
  })

  function selectOption(option: DecisionTreeOption): SelectOutcome | null {
    if (!currentNode.value) return null
    answers.value.push({ nodeId: currentNode.value.id, optionId: option.id })
    if (option.nextId === null && option.result) {
      const payload: DecisionTreeCompletePayload = {
        answers: [...answers.value],
        result: option.result,
      }
      return { type: 'complete', payload }
    }
    if (option.nextId !== null && data.nodes[option.nextId]) {
      currentNodeId.value = option.nextId
      return { type: 'advance', nextNode: data.nodes[option.nextId] }
    }
    // 数据残缺：声明 nextId 但 nodes 中不存在
    console.warn(`[DecisionTree] nextId "${option.nextId}" 不存在于 nodes`)
    answers.value.pop()
    return null
  }

  function goBack(): DecisionTreeNode | null {
    if (!canGoBack.value) return null
    const last = answers.value.pop()!
    currentNodeId.value = last.nodeId
    return currentNode.value
  }

  function reset(): void {
    answers.value = []
    currentNodeId.value = data.rootId
  }

  return {
    currentNodeId,
    answers,
    currentNode,
    isRoot,
    canGoBack,
    empty,
    progress,
    selectOption,
    goBack,
    reset,
  }
}
```

**组件骨架（`src/components/DecisionTree.vue`）：**
```vue
<script setup lang="ts">
import { ref, computed, watch } from 'vue'
import { useDecisionTree } from '@/composables/useDecisionTree'
import type { DecisionTreeData, DecisionTreeCompletePayload, DecisionTreeNode, DecisionTreeOption } from '@/types/decision-tree'

const props = defineProps<{
  data: DecisionTreeData
  initialNodeId?: string
}>()

const emit = defineEmits<{
  (e: 'complete', payload: DecisionTreeCompletePayload): void
  (e: 'advance', node: DecisionTreeNode): void
  (e: 'back', node: DecisionTreeNode): void
}>()

const state = useDecisionTree(props.data)
const finished = ref(false)
const finalResult = ref<DecisionTreeCompletePayload | null>(null)

watch(
  () => props.data,
  () => {
    finished.value = false
    finalResult.value = null
    state.reset()
  },
)

function handleSelect(option: DecisionTreeOption) {
  const outcome = state.selectOption(option)
  if (!outcome) return
  if (outcome.type === 'advance') {
    finished.value = false
    emit('advance', outcome.nextNode)
  } else {
    finished.value = true
    finalResult.value = outcome.payload
    emit('complete', outcome.payload)
  }
}

function handleBack() {
  const node = state.goBack()
  if (node) emit('back', node)
}

function handleRestart() {
  finished.value = false
  finalResult.value = null
  state.reset()
}

function handleKeydown(event: KeyboardEvent, options: DecisionTreeOption[], index: number) {
  let nextIndex: number | null = null
  if (['ArrowDown', 'ArrowRight'].includes(event.key)) nextIndex = (index + 1) % options.length
  if (['ArrowUp', 'ArrowLeft'].includes(event.key)) nextIndex = (index - 1 + options.length) % options.length
  if (nextIndex !== null) {
    event.preventDefault()
    const target = (event.currentTarget as HTMLElement).parentElement?.querySelectorAll('[role="radio"]')[nextIndex] as HTMLElement | null
    target?.focus()
  }
}
</script>

<template>
  <div data-testid="decision-tree" class="decision-tree">
    <!-- 空状态 -->
    <div v-if="state.empty.value" class="dt-empty">
      决策树数据为空
    </div>

    <!-- 结果态 -->
    <div v-else-if="finished && finalResult" class="dt-result">
      <div data-testid="dt-result" class="dt-result__text">
        推荐方案：{{ finalResult.result.planName }}
      </div>
      <el-button data-testid="dt-restart" @click="handleRestart">重新选择</el-button>
    </div>

    <!-- 问答态 -->
    <div v-else-if="state.currentNode.value" class="dt-question">
      <h2 data-testid="dt-question" class="dt-question__title">
        {{ state.currentNode.value.question }}
      </h2>

      <div class="dt-options" role="radiogroup" aria-label="决策选项">
        <button
          v-for="(opt, idx) in state.currentNode.value.options"
          :key="opt.id"
          :data-testid="`dt-option-${opt.id}`"
          role="radio"
          :aria-checked="false"
          :aria-label="opt.label"
          class="dt-option"
          @click="handleSelect(opt)"
          @keydown="handleKeydown($event, state.currentNode.value!.options, idx)"
        >
          {{ opt.label }}
        </button>
      </div>

      <div class="dt-footer">
        <el-button
          data-testid="dt-back"
          :disabled="!state.canGoBack.value"
          @click="handleBack"
        >
          上一题
        </el-button>

        <div data-testid="dt-progress" class="dt-progress">
          {{ state.progress.value.current }} / {{ state.progress.value.total }}
          <span data-testid="dt-progress-dots" class="dt-progress__dots">
            <span
              v-for="i in state.progress.value.total"
              :key="i"
              :class="['dt-dot', { 'dt-dot--filled': i <= state.progress.value.current }]"
            />
          </span>
        </div>
      </div>
    </div>
  </div>
</template>
```

**关键设计决策：**

1. **composable 与组件分离**：业务逻辑放在 composable，便于纯函数单元测试（无需 mount 组件），降低测试复杂度。
2. **不内置结果页跳转**：组件只 `emit('complete')`，由父组件（Story 3-3）决定跳转，保持纯展示职责。
3. **进度估算保守取整**：决策树可能分叉，不同路径深度不同，使用「当前已答题数 + 当前节点到任意叶子的最大深度」作为分母，简单且不会超过 100%。
4. **环检测**：`estimateMaxDepth` 使用 visited 集合，避免数据错误时无限递归。
5. **数据残缺容错**：`selectOption` 遇到 `nextId` 指向不存在的节点时，回滚 `answers` 栈并 `console.warn`，不让组件卡死。
6. **结果态保留在组件内**：仅展示「推荐方案名」+「重新选择」按钮，避免父组件未监听 complete 时用户无感知。

### 接口契约（组件 props/emits）

| 接口 | 类型 | 说明 |
|------|------|------|
| Prop `data` | `DecisionTreeData` | 决策树数据（必填） |
| Prop `initialNodeId` | `string` | 起始节点（默认 `data.rootId`） |
| Emit `complete` | `(payload: DecisionTreeCompletePayload) => void` | 到达叶子时触发 |
| Emit `advance` | `(node: DecisionTreeNode) => void` | 前进到下一题时触发（可选监听） |
| Emit `back` | `(node: DecisionTreeNode) => void` | 返回上一题时触发（可选监听） |

### 性能考虑

- 决策树数据通常 < 50 节点，`estimateMaxDepth` 每次重算可接受；若数据规模大可加 memo（当前 Story 不需要）。
- 选项按钮使用原生 `<button>`，比 `el-button` 渲染更轻。
- 过渡动画使用 CSS transition（不使用 JS 动画库），并尊重 `prefers-reduced-motion`。

### 安全考虑

- 组件不渲染用户输入的 HTML，**禁止**使用 `v-html`，所有文案通过 `{{ }}` 文本插值。
- 选项 `label` 来自前端硬编码数据（Story 3-2 设计），不来自后端 API，无 XSS 风险。

### 测试要求

- **composable 测试**：纯逻辑，禁止 mount 组件，禁止依赖 DOM。
- **组件测试**：使用 `@vue/test-utils` 的 `mount`，禁止使用 `shallowMount`（需要验证子元素渲染）。
- **Mock 规则**：本组件无外部依赖，**禁止** mock element-plus / vue-router。
- **覆盖率目标**：composable 分支覆盖率 ≥ 90%，组件渲染分支 ≥ 80%。
- **手动测试场景**：
  1. 桌面浏览器完整走完一条问答路径 → 显示推荐方案 → 重新选择 → 回到第 1 题
  2. 移动端（Chrome DevTools 模拟 iPhone）布局正常
  3. 键盘 Tab + 方向键 + Enter 全流程操作
  4. 空数据渲染空状态、不报错
  5. 快速连续点击不同选项 → 不出现状态错乱（每次点击都会推进，ansync 状态变更）

### Story 2-6 学到的经验

- **类型严格化**：禁止 `any[]`，所有响应数据定义明确接口（本 Story 全部类型在 `decision-tree.ts` 集中定义）。
- **测试组织**：单元测试与组件测试分文件，避免一个测试文件膨胀。
- **边界用例覆盖**：空数据、非法输入、超长输入都要有用例（本 Story 加入环检测、nextId 指向不存在节点的容错）。
- **测试 testid 命名**：稳定 testid 是 UI 集成测试与 E2E 的基础（本 Story 在 AC #11 中显式列出全部 testid）。
- **不修改预存代码**：发现预存问题（如 vue-tsc tsconfig 选项）不修复，避免本 Story 范围蔓延。

### Story 2-5 学到的经验

- **跨页面竞态防护**：本 Story 无网络请求，但 composable 内部状态变更需保持原子（selectOption 中先 push answers，再判断叶子；失败时 pop 回滚）。
- **`watch` props 变化重置状态**：父组件切换 `data` 时，组件需 `reset()` 并清空结果态。

### Story 2-4 学到的经验

- **mark + 条件渲染**：本组件使用 `v-if/v-else-if/v-else` 三态切换，避免在同一 DOM 节点上动态切换内容造成过渡抖动。

### Story 2-3 学到的经验

- **统一入口函数**：composable 暴露 `selectOption / goBack / reset` 三个语义明确的方法，避免父组件直接操作 ref。
