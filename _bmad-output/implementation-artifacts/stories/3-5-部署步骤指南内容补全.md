# Story 3.5: 部署步骤指南内容补全

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 用户,
I want 查看每个推荐方案的详细分步骤部署指南,
So that 我可以按步骤完成第一次部署。

## Acceptance Criteria

> 本 Story **补全 Story 3-4 步骤指南页中的占位步骤数据**，将 `StepGuideView.vue` 中的 `placeholderSteps` 替换为真实、可执行的部署步骤。本 Story 不涉及新增页面/路由（已由 Story 3-4 完成），不修改复制功能（已由 Story 3-4 完成）。

1. **Given** `deploymentPlans` 中已有 12 个方案注册表
   **When** 本 Story 创建步骤指南数据
   **Then** 为每个 `planId` 编写 3-8 个部署步骤
   **And** 每个步骤包含：`title`（标题）、`description`（描述）、`command?`（可一键复制的命令，可选）、`estimatedMinutes?`（预计耗时，可选）
   **And** 每个 `planId` 至少有一个步骤
   **And** 步骤命令必须是真实可执行的命令或代码片段

2. **Given** 用户访问步骤指南页 `/deployment/decision-tree/steps/:planId`
   **When** `StepGuideView.vue` 渲染
   **Then** 从真实步骤数据源读取步骤，替换现有 `placeholderSteps`
   **And** 显示每个步骤的标题、描述、命令（如有）、预计耗时（如有）
   **And** 步骤总数等于该方案的真实步骤数

3. **Given** 某步骤包含 `command`
   **When** 渲染该步骤
   **Then** 显示代码块
   **And** 显示「一键复制」按钮
   **And** 点击后调用 `copyToClipboard` 复制命令
   **And** 复制成功后按钮文案变为「已复制」

4. **Given** 某步骤不包含 `command`
   **When** 渲染该步骤
   **Then** 不显示代码块和复制按钮
   **And** 仅显示标题和描述

5. **Given** 步骤指南页显示真实步骤
   **When** 页面渲染完成
   **Then** 显示该方案的总预计耗时（所有 `estimatedMinutes` 之和）
   **And** 总耗时文案为「预计总耗时：约 X 分钟」
   **And** 如果某步骤没有 `estimatedMinutes`，则该步骤按 0 分钟计算

6. **Given** 用户在移动端（宽度 < 768px）
   **When** 浏览步骤指南
   **Then** 代码块支持横向滚动
   **And** 复制按钮在代码块下方占满宽度
   **And** 步骤卡片垂直堆叠

7. **Given** 运行数据校验测试 `frontend/src/data/__tests__/deployment-plan-steps.spec.ts`
   **When** 测试执行
   **Then** 验证每个 `planId` 在 `deploymentPlans` 中都有对应的步骤
   **And** 验证每个步骤的 `title` 和 `description` 非空
   **And** 验证 `estimatedMinutes`（若存在）为大于 0 的整数
   **And** 验证 `command`（若存在）非空字符串

8. **Given** 运行组件测试 `frontend/src/views/__tests__/StepGuideView.spec.ts`
   **When** 测试执行
   **Then** 验证真实步骤被渲染
   **And** 验证总预计耗时被渲染
   **And** 验证不包含 `command` 的步骤不显示复制按钮
   **And** 验证复制按钮交互（成功/失败）

9. **Given** 运行构建命令
   **When** 执行 `npx vite build`
   **Then** 构建成功，无新增 TypeScript 错误

**StepGuideView.vue 修改要点：**

```typescript
// 新增导入
import { deploymentPlanSteps } from '@/data/deployment-plan-steps'
import type { DeploymentStep } from '@/types/deployment-plan'

// 移除 placeholderSteps

// 新增计算属性
const steps = computed<DeploymentStep[]>(() =>
  props.planId ? deploymentPlanSteps[props.planId] || [] : [],
)

const totalEstimatedMinutes = computed(() =>
  steps.value.reduce((sum, step) => sum + (step.estimatedMinutes || 0), 0),
)
```

```vue
<!-- 部署步骤卡片 -->
<el-card class="sg-steps-card">
  <h2>部署步骤</h2>
  <p v-if="totalEstimatedMinutes > 0" data-testid="sg-total-time">
    预计总耗时：约 {{ totalEstimatedMinutes }} 分钟
  </p>

  <div class="sg-steps">
    <div
      v-for="(step, idx) in steps"
      :key="idx"
      class="sg-step-item"
      :data-testid="`sg-step-${idx}`"
    >
      <h3>{{ step.title }}</h3>
      <p>{{ step.description }}</p>
      <p v-if="step.estimatedMinutes" class="sg-step-time">
        预计耗时：{{ step.estimatedMinutes }} 分钟
      </p>

      <div v-if="step.command" class="sg-code-block">
        <pre><code>{{ step.command }}</code></pre>
        <el-button
          size="small"
          :type="copiedCommand === step.command ? 'success' : 'primary'"
          @click="handleCopyCommand(step.command)"
        >
          {{ copiedCommand === step.command ? '已复制' : '一键复制' }}
        </el-button>
      </div>
    </div>
  </div>
</el-card>
```

**关键设计决策：**

1. **步骤数据与方案元数据分离**：`deployment-plans.ts` 保存方案元数据，`deployment-plan-steps.ts` 保存详细步骤。职责清晰，避免元数据文件过度膨胀。
2. **步骤命令可选**：并非所有步骤都需要复制命令（例如"注册账号"、"等待构建"）。只有包含 `command` 的步骤才渲染代码块。
3. **预计耗时可选**：允许某些步骤没有明确耗时，总耗时只汇总有值的步骤。
4. **planId 对齐**：`deploymentPlanSteps` 的 key 必须与 `deploymentPlans` 的 key 严格一致，数据校验测试守护。
5. **不修改 DeploymentPlan 接口**：通过新增 `DeploymentStep` 类型和独立注册表，保持向后兼容。

### 接口契约

| 导出 | 文件 | 类型 | 用途 |
|------|------|------|------|
| `DeploymentStep` | `@/types/deployment-plan` | interface | 单个步骤的数据结构 |
| `deploymentPlanSteps` | `@/data/deployment-plan-steps` | `Record<string, DeploymentStep[]>` | planId → 步骤数组的注册表 |

### 性能考虑

- 步骤数据为静态对象，无响应式开销。
- `steps` 和 `totalEstimatedMinutes` 使用 `computed` 缓存。
- 数据规模：12 个方案 × 平均 5 个步骤 ≈ 60 条记录，文件大小 < 15KB（gzip 后 < 5KB），直接 `import` 无需懒加载。

### 安全考虑

- 步骤命令来自前端硬编码数据，不渲染用户输入，无 XSS 风险。
- 命令中若包含占位符（如 `yourname`/`your-repo`），需用中文注释说明用户需要替换。
- 不使用 `v-html` 渲染任何内容。

### 测试要求

- **数据校验测试**：纯数据断言，禁止 mount 组件。
- **组件测试**：使用 `@vue/test-utils` 的 `mount`。
- **Mock 规则**：
  - 继续 mock `element-plus` 的 `ElMessage`（与 Story 3-4 一致）
  - 继续 mock `@/utils/copy-to-clipboard`（与 Story 3-4 一致）
- **覆盖率目标**：
  - 数据校验测试：覆盖全部 12 个 planId
  - 组件测试：覆盖真实步骤渲染、总耗时、复制交互、无命令步骤

### Review Findings

#### decision-needed（需用户决策）

- [ ] [Review][Decision] 多行 command 的复制执行体验 — `github-pages`、`vps-docker`、`self-hosted-k8s` 等方案的 command 包含 `\n` 换行符，用户一键复制后在某些终端直接粘贴可能只执行第一行。是否拆分为多个单命令步骤，或在 description 中说明「请逐行执行」？

#### patch（已确认可自动修复）

- [ ] [Review][Patch] 空步骤数组无友好提示 [`StepGuideView.vue:27`] — 当 planId 存在但 `deploymentPlanSteps[planId]` 为空数组时，页面显示"部署步骤"标题但下方无内容。应增加 `steps.length === 0` 的友好提示。
- [ ] [Review][Patch] command / title / description 纯空格校验漏洞 [`deployment-plan-steps.spec.ts`] — 数据校验使用 `toBeTruthy()`，纯空格字符串可通过校验但 UI 渲染空白。应改为 `.trim().length > 0` 检查。
- [ ] [Review][Patch] 复制功能竞态与定时器泄漏 [`StepGuideView.vue:48`] — `handleCopyCommand` 每次设置新的 `setTimeout` 但不清理旧的，快速点击多个命令时旧定时器会提前将 `copiedCommand` 设为 null。应使用 `clearTimeout` 管理。
- [ ] [Review][Patch] 复制失败后状态未重置 [`StepGuideView.vue:57`] — `catch` 块仅显示 `ElMessage.error`，`copiedCommand` 保持原值，按钮可能仍显示"已复制"。
- [ ] [Review][Patch] externalUrl 无运行时格式校验 [`StepGuideView.vue`] — `plan.externalUrl` 直接绑定到 `:href`，虽有类型注释要求 `https://` 开头，但无运行时校验。建议增加 `https://` 前缀守卫。
- [ ] [Review][Patch] v-for 使用数组索引作为 key [`StepGuideView.vue:186`] — `:key="idx"` 在静态数据下无问题，但不符合 Vue 最佳实践。建议使用稳定唯一标识（如 `step.title` 或 `${planId}-${idx}`）。
- [ ] [Review][Patch] sg-error testid 从完整性测试移除 [`StepGuideView.spec.ts`] — "所有必需 testid" 断言中移除 `sg-error`，导致错误状态 DOM 可访问性回归无法被捕获。应恢复。
- [ ] [Review][Patch] copyToClipboard 测试动态 import 与 mock 不一致 [`StepGuideView.spec.ts`] — 测试体内使用 `await import('@/utils/copy-to-clipboard')`，而文件顶部已有 `vi.mock`。应统一使用 mock。
- [ ] [Review][Patch] railway 方案 command 使用非标准 shell 语法 [`deployment-plan-steps.ts`] — `DATABASE_URL=${{Postgres.DATABASE_URL}}` 是 Railway 平台变量插值，不是可直接执行的 shell 命令。应改为描述性文本或标准 shell 命令。
- [ ] [Review][Patch] Flannel 安装命令引用 master 分支 RAW URL [`deployment-plan-steps.ts`] — `https://raw.githubusercontent.com/flannel-io/flannel/master/Documentation/kube-flannel.yml` 可能随上游变更失效。建议指向稳定版本 release URL。
- [ ] [Review][Patch] 未检查 deploymentPlanSteps 中多余的 planId [`deployment-plan-steps.spec.ts`] — 数据校验只检查 `deploymentPlans` 中的 planId 在 steps 中存在，未检查反向一致性，可能产生孤立步骤数据。
